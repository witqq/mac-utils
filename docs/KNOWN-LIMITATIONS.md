# Known limitations

[Русская версия](KNOWN_LIMITATIONS.ru.md)

- Mac Utils requires macOS 26 or later. Older macOS releases are not supported.
- Storage results are dated metadata snapshots, including when reopened from cache. Refresh is explicit; nested changes, moved roots and stale selections require another scan before cleanup. Successful Trash revises known cached totals and preserves browsing without scanning again; unrelated changes still require Refresh. The original scan date/coverage stays unchanged. These known-size adjustments do not measure freed space. Caches are not freshness or deletion-safety proofs.
- Logical size, filesystem allocation and volume capacity are different measures. Hard-link contributions count once within the scanned root; packages are aggregates. APFS clones/shared blocks and snapshots prevent allocated sums or Trash operations from predicting exclusively occupied or reclaimable space. Trash is not emptied by Mac Utils.
- Supported native APFS volume roots use the public filesystem catalog; folders and explicitly unsupported catalogs use directory traversal. Startup-disk analysis includes verified System/Data firmlink mappings without counting their aliases twice. Unrelated mounted volumes, symlink targets and cloud-only directory contents are excluded. A catalog can omit protected records without reporting errors: its coverage always remains unverified, and the interface warns even when the skip list is empty. Full Disk Access does not turn that result into proof of complete coverage.
- Scanning disables cloud-placeholder materialization for each synchronous metadata operation and restores the worker thread's policy afterward. If that protection cannot be enabled, scanning fails. Catalog mode uses native dataless flags and blocked metadata I/O rather than querying legacy iCloud download status. Catalog-generation, unsafe directory namespace and unrecognized final identity errors stop the run; only explicit lack of catalog support permits traversal fallback. A confirmed catalog leaf replacement at the same verified parent/name keeps the first historical row and its sizes once, omits the incoming contribution and marks the row/ancestors incomplete with an analysis note. This narrow exception does not make the result a current filesystem view; root/ancestor checks stay strict and cleanup rejects the changed identity. Directory changes, contradictory same-identity metadata and unknown proof/SQL failures still stop analysis. Runtime depends on disk contents, permissions and filesystem behavior; no fixed completion time is guaranteed.
- Successfully published schema-3 trees retain the analyzed hierarchy, while their JSON summary and largest list stay bounded. UI branches load 200 children per page through Show More; sibling sorting and map focus read the index without scanning source files. Maps show at most 255 positive-size children plus a nonselectable remainder; the largest list shows up to 200 files/whole packages. Map/list limits do not remove indexed children. Up to 1,000 issue details are retained, with others counted. Context caches, exact hard-link identities and expanded UI pages still consume memory; it is not constant.
- Progress shows phase, elapsed time, processed objects, average rate and counted sizes. When a volume object count is available, the catalog percentage is approximate and stays below 100% until the reading phase ends; result validation still follows. Ordinary folder traversal has no reliable total-count percentage.
- Folder/package navigation uses one saved tree and date. Package internals are browsable but cannot be trashed separately. Refresh scans the selected saved root rather than the focused branch. Older schema-1 full trees remain readable; schema-2 compact overviews need one explicit Refresh to build the tree. Finder reveals the first selected item; confirmed Trash can process multiple selections. The size map starts hidden and can be resized with the standard split divider.
- The JSON cache holds at most twelve roots within 32 MiB, separately from private SQLite tree generations with a soft 8 GiB budget and a 512 MiB free-space reserve during building. Whole inactive generations can be removed; active/newest indices take priority and active readers defer removal until release. Completed full trees become latest even with unverified catalog coverage; an earlier complete result remains a separate backup. Legacy incomplete compact results retain the previous complete cache. Oversized summaries may remain visible uncached. Manage describes metadata removal; clearing results preserves bookmarks, reset also forgets them. Scanned files and macOS permissions are unchanged.
- Storage cleanup first checks canonical saved-tree membership, then current identities and containment. It rejects package internals, scan roots, protected system trees, account/container homes and their ancestors, and the app's own tree cache/ancestors. Its entire tree cache is excluded from analysis with a note; scanning the cache itself is refused. Tree revisions require native copy-on-write cloning of the private cache filesystem; the first update of an older format-1 index may spend time creating metadata indices. Prune failure after native moves preserves a historical browser with more Trash disabled until Refresh. Manifest-write failure preserves the accurate session revision with a warning; it may not survive restart. A reopened older result is read-only until explicit Refresh. Durable protection is saved before native moves; failure to record it refuses cleanup. Other overlapping results are invalidated, and superseded generations cannot mutate again. These failures never undo native moves. Native Trash remains path-based: concurrent replacement after the last check cannot be eliminated. Moved roots keep grant identity, but historical-path cleanup is refused until refreshed.
- Store folder grants and bookmark entitlements compile in both release configurations, but live selected-folder access in a signed Store build remains unverified locally. Disk Access explains optional Full Disk Access and opens macOS privacy settings; users enable it themselves. It may reduce protected-folder requests but does not replace Store selection grants or remove every system restriction. The app does not probe private files to certify the permission. Native navigation can fail; follow the displayed manual Settings route.
- A display that is currently an inactive mirror may expose only its hardware fallback name until it is extended again. Mac Utils still identifies it by its stable CoreGraphics UUID.
- Independent modes and relative positions can be restored only from trustworthy history for the same stable display UUID. Geometry also needs the remembered current-main position as a common reference. Missing or partial history uses deterministic planned placement for displays whose geometry cannot be restored, even if their saved modes are available; a newly independent display falls back to the right. Launching into an already mirrored group cannot reconstruct an unseen arrangement. Unavailable saved modes fall back to a default/native mode compatible with the current rotation. If the catalog offers neither, the current mode remains. macOS may normalize unsupported gaps or overlaps.
- Mac Utils reads rotation but does not change it through private APIs. A saved/current rotation mismatch rejects saved-mode restoration and requires macOS Displays settings. Both-member mode/layout restoration is covered by simulated driver tests and a physical round-trip in both mirror directions on Odyssey G61SD (main, 2560×1440 at 120 Hz, rotation 0°, origin 0,0) and G27Q (extended to its right, 1440×2560 at 72 Hz, rotation 270°, origin 2560,0). The native final state matched the starting roles, coordinates, logical/pixel modes, refresh rates and rotation; the user confirmed uncropped portrait rendering and right-side placement. This evidence covers the observed pair and arrangement; other hardware/configurations require verification.
- Mac Utils does not save or restore the positions of other applications' windows. macOS may rearrange windows whenever display roles or layout change.
- macOS or another application may reserve a global key combination. Mac Utils reports that registration failure and keeps an existing assignment unchanged when an edit cannot be applied.
- macOS may require the user to approve automatic launch in System Settings. Mac Utils cannot bypass that system decision.
- **Refresh Universal Control** is available only in Direct builds and is compiled out of the Mac App Store build. It restarts local Continuity processes, can briefly interrupt related Apple services, and cannot guarantee reconnection when the underlying Universal Control requirements are not met. It does not pair or transfer a Magic Trackpad. See the [feasibility report](MAGIC_TRACKPAD_FEASIBILITY.md).
- **Dismiss all notifications** is available only in Direct builds and is compiled out of the Mac App Store build. It requires Accessibility access, relies on the Notification Center's accessibility structure (its four notification subroles, including the two stack subroles) and the localized names of its Close and Clear All actions (read from the system bundle), and may need an update after a macOS release that changes that structure. Notifications that arrive while the action is running are not chased. A script run from a global shortcut does not display its failure message in the app; a missing permission is visible only through the macOS prompt.
- Signed release work requires the Apple Developer identities and `mac-utils-notary` Keychain profile described in [Signing and notarization](SIGNING.md). These credentials are local or cloud-managed and are intentionally not stored in the repository.
